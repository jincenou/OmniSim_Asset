# 资产与运行产物保护边界

源码仓库不包含、也不自动清理资产库。整理旧运行目录前，需要把下列对象作为保护集合：

1. `asset_library/` 全部子目录，包括 rigid、human、payloads、manifests、exports、releases、dataset_splatad 和相关来源记录。
2. 资产库符号链接、manifest、runtime、相机或动作侧车实际指向的外部 payload。
3. 已交付网络人体包及其回放依赖，例如 `4danyone/web_people/*/assets`，以及用于交付的连续动作／循环回放文件。
4. 已结算实验的冻结清单、逐对象结果、协议、源资产和验证依据。
5. 当前活动进程正在访问的输入、工作目录、恢复点和日志。

`runs/`、`outputs/`、`chunks/` 只是目录名称，不能据此判定可删除。刚体生产代码曾明确保留中间结果用于之后的跨模型比较；某个早期输出也可能是后来资产库链接的唯一实体。

通常可重新生成的候选包括 `__pycache__`、`.pytest_cache` 和已失效的临时状态写入文件。删除前仍需确认它不在保护集合、没有活动写入，且候选是期望的普通文件／目录。历史 cleanup 脚本只作为源码保留，不能批量执行来代替本次具体盘点。

本仓库的物化工具只复制文本源文件，拒绝覆盖已有文件并拒绝通过符号链接父目录写入；它不下载、迁移或删除已有资产。
